# Repository package editor

The Agents tab links to `agents/package`. The page renders a small authenticated shell; it does not scan files or resolve dependencies. Opening a manifest performs one existing `contents` read of the selected branch's root `gild.json`, through the browser compatibility adapter and the same private repository read policy. The response identifies the immutable commit and blob. Missing prepared content returns Pending and can be retried.

`lib/api/agent-package-contract.ts` remains the sole portable definition schema; `scripts/generate-api-client.mjs` emits the literal source with its existing header. Inline and dependency/member agent definitions, repository/ref/bundlePath dependencies and requested permissions are declarative. This UI neither resolves latest nor installs, enrolls or launches agents. It does not read referenced assets or credential/system directories. Definitions remain committed Git files; there is no SQL definition store.

`PUT /api/v1/repos/{owner}/{repo}/agent-package` is the registered canonical operation. The browser adapter uses the existing verified session, same-origin CSRF and shared API dispatch. Its strict input is `{branch, expected_head, text}`. Current repository read and human write ACLs, token scope/allow-list and lifecycle restrictions are checked; a read-only collaborator has no editing control and is denied at the API. Arbitrary paths and identity/grant fields are rejected.

The server validates the exact manifest text and edits only the already-present regular root `gild.json`. It reuses the validated immutable root entries, preserving other files and executable modes even when a second index read would be unavailable. Existing Git pack helpers build the blob/tree/commit; the existing Git proxy path retains repository write serialization, import ownership refusal, rate/storage/ref/pre-receive checks and final receive-pack expected-head CAS. External receive-pack still requires Bearer/Basic authentication; no browser Gild API token is created or exposed. The ordinary internal Artifacts connection remains inside the established server Git mechanism.

HTTP200 alone does not confirm a save: unpack and the exact updated ref must be acknowledged. A stale HEAD is a conflict; UI errors retain the draft and require reloading/checking the branch before another save. Only confirmed responses update the displayed commit. Editing manifest bytes does not rewrite `gild.lock`; the CLI must explicitly update the lock/install selection as appropriate.

Focused evidence: `scripts/agent-package-ui-local.mjs` uses a disposable private repository and actual compiled Worker/browser to exercise multiple members, references, validation/cancel, authorized save, reader/outsider/CSRF denial, unchanged external Git authentication, fixed-file writes and stale CAS conflict. `lib/agent-package-write.test.ts` uses a volatile index and real local receive-pack: omitting root reuse removes unrelated files and fails; restoring it preserves their bytes/modes. These fixtures establish local effects, not live HTTPS authorization or deployment.
