# Prepared health API reads

`health` and `healthAt` now use the same current-policy D1 access/read service as prepared refs. Their existing successful response shapes, authentication boundary and incomplete-report behavior are preserved. Missing preparation returns the established typed503 error; an actually prepared unscored report returnsnull. Zero-line incomplete reports still expose null scores and remain no-store. Complete explicit immutable-hash reports retain their existing cache semantics, subject to current access.

A data-only CQX build identity, shared with the existing pinned module adapter, keeps the reader cache namespace aligned without importing the scorer. Reports are keyed by canonical repository identity, immutable commit hash and exact tool/reads version. Producers publish actual computed or cached reports into additive source migration0023. An incomplete producer outage cannot replace a completed immutable report. A moving branch uses fenced prepared refs; an explicit historical immutable report can be served independently of a branch refresh after current ACL checks.

Dispatch/authorize/execute share a request-local authorization snapshot through a WeakMap keyed by the Request object. It expires with that request and is never a cross-viewer or cross-request policy cache. A real registered read asserts at most six D1 query round trips, preventing repeated authorization queries at each service layer; removal of this reuse fails that effect. Writers and other operations retain their original providers.

Registered dispatcher/service/native-SQLite effects disable all legacy/Git/index/scorer/network ports on GET. Effects distinguish missing, wrong-version and prepared null reports, incomplete scores/no-store, moving-ref fences, immutable completion surviving outage, canonical case and current ACL revocation. Removing the version key, immutable-complete guard or request-local reuse fails the respective actual effect; source is restored. Actual compiled Worker HTTP checks prepare reports with the real RepoIndex producer before the read baseline, then schema-validate health/healthAt alongside six existing prepared GETs with zero Git reads during GET.

Initial fixture setup failures are retained: an extensionless reads import in native Node, removal of the pin import still used by module identity verification, a synthetic report missing the required calibrated flag and an anonymous test incorrectly expecting404 instead of the existing authenticated401. These were corrected without loosening the registered schemas, policy or test assertions.

Source/additive migration and local fixture evidence do not establish a matching complete Cloudflare build, remote migration application or deployment. Diff adapters and the broader rich API/search/SSR migration remain in progress. No new permission/binding/token/resource or destructive database operation is introduced.
