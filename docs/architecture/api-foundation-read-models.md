# Prepared API read models — first foundation batch

`lib/api/contract.ts` is the sole route authority. `lib/api/read-contract.ts` owns the new card/display/viewer DTOs and stable preparation code; the existing generator copies it literally with its header. These shared D1 readers are intended for both registered HTTP handlers and subsequent SSR migration, not a browser-only data layer.

## Current implemented slice

- `GET /api/v1/owners/{owner}/repositories`: card-specific envelope, bounded page/per_page, current per-row ACL/lifecycle/org/agent/allowlist authorization before pagination. Reads only prepared catalogue receipts and primary D1 projections/stars. It cannot call Artifacts, DO.listing, Git, an index wait, a scorer, or a build.
- `GET /api/v1/owners/{owner}/profile`: explicitly safe public display fields and resolved picture. Never serializes claims, keys, claim emails, PageReads or raw viewer records. Existing self/admin org profile operations retain their authority.
- `GET /api/v1/viewer/context`: private/no-store authenticated viewer and optional paired owner/repo context. Capabilities are operation-specific: manifest edit, non-default/default branch push and repository-settings update. Agent pr plus repo:write grants non-default push only; every actual mutation still applies its original current policy/ref/quota/import/CAS fences. Roles alone never override token scopes/allowlists or lifecycle.

Missing catalogue/projection or pending/mismatched current ACL yields the existing error response status **503**, `Retry-After: 1`, and `errors[0].code = PREPARATION_PENDING`. Successful legacy arrays/payloads are unchanged. Unknown owner/repository and inaccessible private targets retain **404**; a collection omits unauthorized rows before pagination/readiness. A producer-certified empty catalogue yields a ready empty collection. No certificate means Pending, not invented empty success.

`repo_listing` facts already include language/license/absolute activity weeks/open counts. The producer now records `factsTip`; retained old/legacy facts without matching provenance yield `summaryPending: true` and no current facts. Creation/push timestamps come only from observed catalogue fields or null, never invented defaults.

## Preparation and reconciliation

The additive migration0021 introduces producer-owned catalogue rows/receipts. Publication commits one observed complete inventory atomically with its receipt, including genuinely empty inventories. Rows are retired non-destructively; generation joins and observation ordering prevent an older completion from resurrecting removed entries. The existing cron reconciles one known current owner at a time (oldest first), uses the existing catalogue source in that background lane, and explicitly schedules index ingestion for its repositories. Source failure cannot certify an empty inventory. The receipt publisher bounds inventories at1000, but the current external source request caps at200. The source adapter rejects a full200 result because it cannot prove that inventory is complete. Such catalogues stay Pending until paginated producer reconciliation is added; there is no partial-list certificate.

Existing proxied push/metadata/import completion ingestion hooks and writer `readyIndex`/CAS providers are preserved. Mutable profile, stars, membership, ACL and run facts remain independent of immutable code-fact caches. No migration was applied remotely, new scope/binding/resource provisioned or token minted by this source checkpoint.
